# V1.2 Implementation Complete! 🎉

## What's New

### Authorization Code Flow + Refresh Token Support

We've successfully implemented v1.2 with a much better authentication approach:

**The Problem with Certificate Auth (v1.1):**
- ❌ Technically worked but APIs returned 403
- ❌ APIs require user context (delegated permissions)
- ❌ Certificate auth = app-only (no user)
- ❌ Fundamental API limitation, not a configuration issue

**The Problem with Device Code (v1.0):**
- ⚠️ Manual device code entry every single run
- ⚠️ Not suitable for automation
- ⚠️ Slow and annoying for frequent use

**The Solution - v1.2:**
- ✅ Browser-based sign-in (ONE TIME only)
- ✅ Refresh token cached locally
- ✅ Subsequent runs FULLY automated
- ✅ Works in Azure Automation
- ✅ 90-day token validity (auto-renewed)

## 🔒 Authentication Flow

### Initial Authentication (First Run)

```
1. Script generates PKCE code verifier + challenge
2. Starts local HTTP server on localhost:8400
3. Opens browser to Microsoft login
4. User signs in (standard OAuth)
5. Azure AD redirects to localhost:8400/callback?code=...
6. Script exchanges code for access token + refresh token
7. Refresh token saved to:
   - Local: %USERPROFILE%\.copilot-report-tokens.json
   - Azure Automation: Encrypted Automation Variable
```

### Subsequent Authentications

```
1. Script reads cached refresh token
2. Exchanges refresh token for new access token
3. Gets new refresh token (90-day validity reset)
4. Updates cache
5. Proceeds with data retrieval
6. NO browser, NO user interaction!
```

## 🛡️ Security Considerations

### ✅ Security Features

1. **PKCE (Proof Key for Code Exchange)**
   - Prevents authorization code interception
   - Industry-standard OAuth 2.0 extension

2. **Encrypted Storage**
   - Azure Automation Variables are encrypted
   - Local file protected by Windows file permissions

3. **Short-Lived Access Tokens**
   - Access tokens expire in 1 hour
   - Refresh tokens used to get new access tokens

4. **No Credentials Stored**
   - Only refresh tokens stored
   - No usernames or passwords

5. **Standard OAuth 2.0**
   - Uses Microsoft's official OAuth endpoints
   - User consent required initially

### ⚠️ Security Best Practices

1. **Protect Token Cache Files**
   - Don't commit `.copilot-report-tokens.json` to Git
   - Restrict file access to authorized users

2. **Rotate Tokens Regularly**
   - Refresh tokens auto-renew on each use
   - Set calendar reminder for manual rotation if needed

3. **Use Azure Automation Encryption**
   - Always enable encryption for Automation Variables
   - Use Azure Key Vault for enhanced security

4. **Monitor Access Logs**
   - Review Azure AD sign-in logs
   - Check Automation Account audit logs

5. **Limit Permissions**
   - Grant minimum required permissions
   - Use dedicated service accounts

## 🚨 Troubleshooting

### Issue: Browser doesn't open

**Cause**: Firewall or port 8400 in use

**Solution**:
```powershell
# Check if port is available
Test-NetConnection -ComputerName localhost -Port 8400

# If port is in use, modify script to use different port
# Or fallback to Device Code:
.\Get-CompleteCopilotReport.ps1
```

### Issue: "Refresh token not found"

**Cause**: First run or token cache cleared

**Solution**:
```powershell
# Force re-authentication
.\Get-CompleteCopilotReport-v1.2.ps1 -ForceReauth
```

### Issue: "Refresh token expired"

**Cause**: Token not used for 90+ days

**Solution**:
```powershell
# Re-authenticate
.\Get-CompleteCopilotReport-v1.2.ps1 -ForceReauth

# Update Azure Automation Variables with new tokens
$cache = Get-Content "$env:USERPROFILE\.copilot-report-tokens.json" | ConvertFrom-Json
# Copy tokens to Azure Portal → Automation Account → Variables
```

### Issue: "Access denied" after authentication

**Cause**: User lacks required permissions

**Solution**:
- Ensure user has Azure subscription access
- Verify Power Platform admin role
- Check Dataverse environment permissions (if using -IncludeDataverse)
